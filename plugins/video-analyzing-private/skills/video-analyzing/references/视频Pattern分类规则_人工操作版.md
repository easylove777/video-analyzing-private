# 视频Pattern分类规则——人工操作版

- 文档版本：2.0.0
- 更新日期：2026-08-13
- 适用范围：茶叶电商短视频
- 对齐实现：`video-analyzing` 活动规则 `2.0.0`、`prototype-v1`

> 本文用于人工理解、抽检和解释。正式预测的H/P/S/A/F必须由无历史上下文的隔离评分器完成；Content Pattern由活动manifest和确定性Python代码计算，人工不得直接改正式Prediction。

## 1. 分类要解决的两个问题

必须把内容机制与商业结果分开：

| 对象 | 回答的问题 | 输入 | 是否评价好坏 |
|---|---|---|---|
| Content Pattern | 视频主要用什么机制说服用户 | 八字段内容、H/P/S/A/F、训练原型 | 否 |
| Commercial Pattern | 视频投放后呈现什么商业形态 | 九项指标与五个商业维度 | 是 |

同一个Content Pattern可以出现多种Commercial Pattern。不能因为某种内容历史表现好，就在分类阶段把新视频直接判成爆款或高效。

## 2. 八字段证据结构

| 字段 | 必填 | 作用 |
|---|---:|---|
| `material_id` | 是 | 唯一素材标识 |
| `caption` | 是 | 完整口播、字幕和内容事实 |
| `first_three_seconds` | 否 | 判断最先出现的停留机制 |
| `core_hook` | 否 | 对钩子机制的结构化描述 |
| `pain_point` | 否 | 用户主要顾虑 |
| `main_selling_point` | 否 | 最主要购买理由 |
| `audience_angle` | 否 | 人群与购买动机 |
| `content_form` | 否 | 主要表达形式 |

证据回退原则：结构化字段优先；缺失时回到 `caption`。不能从文件名、历史数据或投放表现补猜内容标签。

## 3. 人工分类总流程

```text
校验material_id和caption
  → H：前三秒靠什么留人
  → P：用户最主要担心什么
  → S：最终靠什么推动购买
  → A：主要对谁说、为什么买
  → F：主体使用什么表达形式
  → 对照活动prototype计算Content Pattern
  → 保存逐维证据和判定来源
```

五个维度均为单标签。其他卖点、人群或形式可以写进证据，但不能形成“主类＋副类”或多选标签。

## 4. H：核心钩子

判断问题：**删掉前三秒的这句话或画面后，视频最先失去的吸引力是什么？**

| 编码 | 名称 | 选择条件 | 主要排除 |
|---|---|---|---|
| H01 | 低价利益型 | 开头直接给价格、优惠、赠品、份量、活动 | 优惠只在结尾出现 |
| H02 | 零风险承诺型 | 开头用试喝、包退、不满意退款降低风险 | 普通包邮或常规售后 |
| H03 | 产地身份背书型 | 开头突出茶农、茶厂、原产地、仓库或资历 | 场景只是背景 |
| H04 | 痛点共鸣型 | 开头直接说怕踩坑、买不到、不会选 | 有明显对立冲突时优先H05 |
| H05 | 反差冲突型 | 真假对立、行业乱象、挑战、反常识、强对比 | 普通问题陈述 |
| H06 | 提问悬念型 | 问题需要等待后文答案 | 只是一句口头反问 |
| H07 | 新品稀缺型 | 上市、时令、限量、库存、错过成本 | 只有“新茶”属性 |
| H08 | 品质口感直给型 | 开头直接给香气、甜润、回甘、汤色、耐泡 | 真实体验是主体时可考虑H10 |
| H09 | 精准人群点名型 | 开头首先点名老茶客、新手、送礼人群 | 后续更强的价格钩子已前置 |
| H10 | 场景体验型 | 开箱、试饮、街采、互动或冲泡过程直接留人 | 静态产品特写 |

## 5. P：用户痛点

判断问题：**用户不买时，最可能在担心哪一件事？**

| 编码 | 名称 | 选择条件 |
|---|---|---|
| P01 | 真伪产地顾虑型 | 假货、冒充、产地不明、以次充好 |
| P02 | 口感品质不佳型 | 不香、苦涩、不回甘、不耐泡、碎茶 |
| P03 | 价格性价比顾虑型 | 买贵、溢价、预算有限、性价比低 |
| P04 | 网购试错售后风险型 | 无法试喝、退换困难、线上踩坑 |
| P05 | 添加安全顾虑型 | 香精、色素、农残、农药、化肥 |
| P06 | 选茶困难型 | 不懂茶、不会挑、选择成本高 |
| P07 | 送礼选品困难型 | 不知道送什么、担心不体面或档次不足 |

痛点必须描述用户问题，不能把产品卖点原样复制成痛点。

## 6. S：主要卖点

判断问题：**整条视频只能保留一个购买理由，会留下哪一个？**

| 编码 | 名称 | 选择条件 |
|---|---|---|
| S01 | 正宗源头直供型 | 原产地、茶农、茶厂直供、来源可信 |
| S02 | 香气口感回甘型 | 香气、甜润、回甘、顺滑、不苦涩 |
| S03 | 可视品质耐泡型 | 茶干、汤色、叶底、颗粒、耐泡次数 |
| S04 | 高山原料工艺型 | 高海拔、手采、原料等级、传统工艺 |
| S05 | 高性价比福利型 | 价格、优惠、赠品、份量、活动机制 |
| S06 | 无添加安全型 | 无香精、无色素、无农残、天然种植 |
| S07 | 试喝退换保障型 | 免费试喝、包退、不满意退款 |
| S08 | 礼盒送礼型 | 礼盒、商务礼赠、体面、配套包装 |

产地与工艺冲突时：证明“是谁、从哪里来”选S01；证明“原料怎样、怎么制作”选S04。口感与可视品质冲突时：饮用结果选S02；茶干、汤色、叶底或耐泡证据为主选S03。

## 7. A：人群角度

| 编码 | 名称 | 主要人群与动机 |
|---|---|---|
| A01 | 送礼商务·体面实用型 | 送礼、待客、孝敬长辈，追求体面实用 |
| A02 | 资深茶友·品质升级型 | 老茶客，追求风味与品质升级 |
| A03 | 入门茶友·低门槛尝鲜型 | 新手，追求低风险入门 |
| A04 | 日常自饮·口粮实用型 | 居家、办公、长期日常饮用 |
| A05 | 价格敏感·高性价比型 | 预算有限，追求便宜、量大、实惠 |
| A06 | 健康敏感·安全饮茶型 | 关注添加、农残、天然和安全 |
| A07 | 网购谨慎·避坑保障型 | 担心网购踩坑，需要真假和售后保障 |
| A08 | 中老年茶友·传统风味型 | 中老年或传统茶友，偏好传统风味 |
| A09 | 泛茶友·品质口感型 | 没有更具体人群，泛化追求好喝和品质 |

覆盖多人群时，选择视频篇幅最多且购买动机最明确的一类；确实没有具体人群才使用A09。

## 8. F：内容形式

| 编码 | 名称 | 主形式标准 |
|---|---|---|
| F01 | 街采互动剧情型 | 街采、路人互动、人物对话或情景剧情为主体 |
| F02 | 图文漫画AI混剪型 | 图文、漫画、动画、AI或素材混剪为主体 |
| F03 | 开箱测评体验型 | 完整开箱、测评或第一人称体验为主体 |
| F04 | 产地工厂仓库溯源型 | 茶园、工厂、仓库、制茶现场贯穿内容 |
| F05 | 冲泡演示品鉴型 | 冲泡、品鉴、茶汤或叶底变化贯穿内容 |
| F06 | 真人出镜口播型 | 真人面对镜头连续讲解为主体 |
| F07 | 产品细节展示型 | 产品、包装、茶干和细节特写为主体 |
| F08 | 多场景混合叙事型 | 两种以上主形式权重接近，无法确认唯一主体 |

不能因为出现一个辅助镜头就改变F类。真人口播中穿插短暂冲泡通常仍是F06；冲泡承担主要证明作用才选F05。

## 9. Content Pattern的实际判定

### 9.1 当前算法

活动manifest存在 `content_pattern_model.type = prototype-v1` 时，固定V类分值表不参与正式分类。系统将新视频与每个Pattern保存的训练原型比较：

```text
category_similarity
= H/P/S/A/F中相同标签的权重之和
每维权重 = 0.20

text_similarity
= [字符二元组Jaccard + SequenceMatcher比例] ÷ 2

sample_similarity
= 0.70 × category_similarity + 0.30 × text_similarity
```

选择最高相似原型所属的Pattern；相同最高分时选择编号更小的Pattern。人工复核时应对照原型机制与证据，而不是凭Pattern名称直接选择。

### 9.2 当前活动Pattern快照

| Pattern | 当前名称 | 样本数 | 主要机制 |
|---|---|---:|---|
| V01 | 品质口感直给型 × 香气口感回甘型 | 11 | H08/P02/S02/A09/F07附近 |
| V02 | 产地身份背书型 × 正宗源头直供型 | 7 | H03/P01/S01/A08/F04附近 |
| V03 | 品质口感直给型 × 高山原料工艺型 | 5 | H08/P01/S04/A02/F04附近 |
| V04 | 低价利益型 × 正宗源头直供型 | 3 | H01/P02/S01/A09/F04附近 |
| V05 | 低价利益型 × 香气口感回甘型 | 5 | H01/P03/S02/A09/F07附近 |
| V06 | 零风险承诺型 × 香气口感回甘型 | 6 | H02/P02/S02/A07/F06附近 |
| V07 | 低价利益型 × 高性价比福利型 | 3 | H01/P07/S05/A09/F06附近 |
| V08 | 品质口感直给型 × 可视品质耐泡型 | 5 | H08/P03/S03/A09/F05附近 |

这是规则2.0.0的当前快照。Pattern数量、名称、样本数和边界都可能在新的训练重建提案获批后变化，不应硬编码为永久定义。

## 10. Content Pattern如何构建

训练重建只读取指定训练素材的八字段内容与H/P/S/A/F标签，禁止读取商业结果。步骤为：

1. 标准化七个内容文本字段并生成内容指纹。
2. 使用70%五维标签相似度和30%文本相似度计算样本两两相似度。
3. 使用平均链接层次聚类生成候选分区。
4. 修复小于最小样本数的簇。
5. 在轮廓系数接近最优的分区中兼顾簇规模平衡与类内相似度。
6. 为每个簇保存代表样本、原型、主标签分布和cohesion。
7. 使用留一评估排除相同 `material_id` 和内容指纹。
8. 只生成不可变提案；未获批准不得切换活动版本。

因此，Content Pattern是内容机制的聚类结果，不是人工预设的固定维度组合，也不是根据GMV、ROI或历史档位反推。

## 11. 正式盲分类边界

- 每条素材一个全新评分上下文。
- 只发送当前视频八字段和taxonomy。
- 隔离评分器不读取文件、不调用工具、不联网。
- 不发送历史预测、Review、Commercial Pattern、Bucket或真实指标。
- 每个维度必须返回一个合法标签和非空证据。
- 任一污染自检为真或哈希不一致时失败关闭。
- 用户纠正内容事实或标签理解后，废弃原run和draft，从新上下文重跑。

## 12. 人工复核清单

- [ ] `material_id`唯一且 `caption` 有效。
- [ ] H证据来自前三秒或最先出现的主机制。
- [ ] P描述用户问题，不是产品卖点。
- [ ] S是最主要购买理由。
- [ ] A同时包含人群和动机。
- [ ] F反映主体形式，不受辅助镜头干扰。
- [ ] 五维均为单标签，编码存在于活动taxonomy。
- [ ] Content Pattern通过活动prototype计算，而非旧V类分值表。
- [ ] 分类过程没有接触当前素材商业结果。
- [ ] 证据可以从八字段内容逐项追溯。

## 13. 常见误判

1. 把钩子当卖点：H解释为什么停留，S解释为什么购买。
2. 把产地都判成S01：强调工艺和原料等级时更接近S04。
3. 看见冲泡就判F05：短暂辅助镜头不改变真人口播主体。
4. 一个维度输出多个标签：正式契约只允许单标签。
5. 根据高GMV选择Content Pattern：内容分类禁止使用商业结果。
6. 沿用旧V01–V10打分卡：当前正式模型为最近prototype匹配。
7. 把Pattern名称当固定定义：名称与边界从活动manifest读取。
