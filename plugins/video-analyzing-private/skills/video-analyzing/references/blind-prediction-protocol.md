# 盲预测上下文隔离协议

## 目标

预测不只隔离真实字段，还隔离模型已经看过的历史结果和推断痕迹。Python 负责读取活动规则与历史案例、匿名化候选、验证哈希和计算统计；隔离评分上下文只负责内容分类与语义相似度判断。

## 上下文边界

- 每条素材一个全新上下文，批量任务不得在素材之间复用评分上下文。
- 同一素材的 `classification` 与 `similarity` 在同一个新上下文中连续执行，以保留本条素材的内容判断一致性。
- 隔离评分上下文只加载 `video-analyzing-blind-score`，不得加载主 Skill、其他 Skill、此前消息、历史结果或工具输出。
- 隔离评分器不得调用任何工具。所有读取、匿名化、哈希校验、映射恢复和落盘都在主流程完成。
- 任一请求或响应字段、自检、哈希、候选集合、资产版本不匹配时失败关闭：不补猜、不降级为主上下文评分、不生成正式预测。

## 两阶段协议

1. 主流程用 `create_classification_request` 生成只含八字段内容和五维 taxonomy 的请求。
2. 全新隔离上下文返回五维 `labels`、逐维 `evidence` 和自检。
3. 主流程验证响应后读取活动案例库，只把候选内容改写为 `candidate_001` 等盲 ID；真实 `case_id`、`material_id` 与全部商业结果保留在本地映射中。
4. 同一隔离上下文返回所有盲候选的 `semantic_scores`。
5. 主流程校验双阶段请求/响应哈希、同一 `run_id`、同一评分器身份、资产哈希和候选映射哈希，然后生成盲回执。
6. 只有有效盲回执才能生成 prediction schema v4 草稿。

## 草稿与冻结

盲评分完成后先生成不可作为复盘依据的草稿，并完整展示预测结果。用户必须回复精确指令 `确认预测 <draft_id>`，主流程才将草稿冻结为正式 v4 Prediction。确认时必须重新校验草稿哈希、盲回执哈希和活动资产哈希；任一变化均要求重新盲预测。

正式 v4 快照至少保存：`blind_run_id`、`blind_receipt_sha256`、四个阶段哈希、`prompt_version`、`scorer_identity`、活动规则与案例库哈希。v2/v3 只读兼容，不再作为新预测写入格式。

## 批量规则

批量预测按单条状态机执行：为每条素材生成独立请求、独立隔离上下文、独立回执和独立草稿。单条失败不污染其他素材，也不能把其他素材的分类或候选评分带入下一条。
